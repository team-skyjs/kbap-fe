## User Scenarios & Testing *(mandatory)*

### User Story 1 - 식사 시간 알림을 탭하면 홈이 열린다 (Priority: P1)

점심·저녁 식사 시간에 도착하는 알림(식사 시간 유형)을 탭하면 앱 홈 탭이 열린다. 앱이 꺼져 있었으면 홈으로 시작하고, 다른 화면에 있었으면 홈 탭으로 이동한다. 지금은 앱만 켜지고 이동이 없다.

**Why this priority**: 식사 시간 알림은 "지금 스캔해 보라"는 유도인데, 앱만 켜지면 사용자가 어디로 가야 할지 모른다. 홈에는 스캔 진입점과 최근 주문이 있어 자연스러운 출발점이다.

**Independent Test**: 식사 시간 유형 알림을 테스트 발송 → 백그라운드 상태와 종료 상태에서 각각 탭 → 두 경우 모두 홈 탭이 보이면 통과.

**Acceptance Scenarios**:

1. **Given** 앱 백그라운드, 다른 탭 또는 그 위의 화면(내 리뷰 목록·음식 상세 등)에 있던 상태, **When** 식사 시간 알림 탭, **Then** 열려 있던 화면이 전부 닫히고 홈 탭이 표시된다. 뒤로 가기 대상이 없다.
2. **Given** 앱 종료 상태, **When** 식사 시간 알림 탭, **Then** 앱이 홈 탭으로 시작한다.
3. **Given** 앱이 이미 홈 탭, **When** 식사 시간 알림 탭, **Then** 홈 탭 그대로이며 화면이 중복으로 쌓이지 않는다.
4. **Given** 식사 시간 알림 탭, **Then** 알림함에 그 알림이 읽음으로 기록된다(알림함 서버 전환 작업과 연계, 여기서는 착지만 책임).

---

### User Story 2 - 리뷰 좋아요 알림을 탭하면 내 리뷰 목록이 열린다 (Priority: P1)

내 리뷰에 "도움돼요" 반응이 달렸다는 알림을 탭하면 내가 작성한 리뷰 목록 화면이 열린다. 지금은 "착지 미정" 임시 화면으로 간다.

**Why this priority**: 임시 화면은 디버깅용이라 사용자에게 노출되면 안 된다. 서버 알림 데이터에 리뷰 id가 없어 특정 리뷰로 바로 갈 수 없으므로 내 리뷰 목록이 가장 가까운 착지다.

**Independent Test**: 리뷰 좋아요 유형 알림을 테스트 발송 → 탭 → 내 리뷰 목록 화면이 열리고, 뒤로 가면 프로필 또는 이전 화면으로 돌아가면 통과.

**Acceptance Scenarios**:

1. **Given** 회원, 앱 백그라운드, **When** 리뷰 좋아요 알림 탭, **Then** 내 리뷰 목록 화면이 표시된다.
2. **Given** 회원, 앱 종료 상태, **When** 리뷰 좋아요 알림 탭, **Then** 앱이 시작되고 내 리뷰 목록 화면이 표시된다. 뒤로 가기가 동작한다.
3. **Given** 로그인이 풀린 상태(게스트)로 리뷰 좋아요 알림이 남아 있음, **When** 탭, **Then** 내 리뷰 화면의 기존 게스트 처리(로그인 유도 시트)가 그대로 동작한다.

---

### User Story 3 - 임시 착지 화면이 사라진다 (Priority: P2)

"착지 미정 (기획 필요)" 임시 화면과 그 문구가 앱에서 제거된다. 어떤 알림 유형도 그 화면으로 가지 않는다.

**Why this priority**: 디버깅용 화면이 배포 앱에 남아 있으면 사용자에게 노출될 위험이 있다. 착지가 정해졌으므로 존재 이유가 없다.

**Independent Test**: 다섯 유형 + 미지 유형의 탭 경로를 전부 확인해 임시 화면 경로가 하나도 없고, 임시 화면 문구 키가 10개 언어 파일에 없으면 통과.

**Acceptance Scenarios**:

1. **Given** 다섯 알림 유형 각각, **When** 탭 경로 산출, **Then** 임시 화면 경로가 나오지 않는다.
2. **Given** 10개 언어 파일, **Then** 임시 화면 문구 키가 없다.

---

### User Story 4 - 스캔 제안 알림의 착지 (Priority: P2)

스캔 제안 알림(광고성, 배치 발송)을 탭하면 홈 탭이 열린다(식사 시간 알림과 동일한 착지·동일한 동작, 2026-09-16 종한 확정). 홈에 스캔 진입점이 있어 스캔 화면 직행 대신 홈을 택했다.

**Why this priority**: 임시 화면 제거(스토리 3)가 이 결정에 걸려 있었다. 홈으로 확정되어 임시 화면을 지울 수 있다.

**Independent Test**: 스토리 1과 같은 절차를 스캔 제안 유형으로 반복해 두 경로 모두 홈 탭이면 통과.

**Acceptance Scenarios**:

1. **Given** 스캔 제안 알림, **When** 탭(백그라운드·종료 두 경로), **Then** 홈 탭이 표시되며 스토리 1의 시나리오 1~3이 동일하게 성립한다.

---

### Edge Cases

- 알림 유형 값이 알 수 없는 것이면 어떤 화면으로도 이동하지 않고 앱만 켜진다(기존 유지).
- 소식(NEWS) 알림은 이동 없음 유지. 알림함에서 읽는 용도.
- 리뷰 리마인더는 기존 결정(음식 상세) 유지. 음식 id가 없으면 이동 없음.
- 앱 종료 상태에서 알림 탭으로 시작할 때, 시작 시퀀스(스플래시·세션 복구·온보딩 미완료 등)가 끝난 뒤 착지 화면으로 가야 하며, 온보딩 미완료 회원은 온보딩이 우선이다.
- 착지 화면이 회원 전용(내 리뷰)인데 세션이 만료된 경우, 그 화면의 기존 게이트가 처리한다. 착지 로직이 별도 판단을 하지 않는다.
- 같은 알림을 두 번 탭(알림 센터 잔존)해도 화면이 두 번 쌓이지 않는다.
- 서로 다른 알림을 연달아 탭해도 목적 화면이 이미 맨 위면 재사용한다(내 리뷰 목록 1장 유지, 음식 상세는 새 음식으로 갱신). 맨 위가 다른 화면이면 그 위에 연다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 식사 시간(MEAL_TIME) 알림 탭은 홈 탭으로 이동해야 한다. 홈 위에 열려 있던 화면은 전부 닫는다(뒤로 가기 대상 없음). 이미 홈이면 그대로 둔다.
- **FR-002**: 리뷰 좋아요(HELPFUL) 알림 탭은 내가 작성한 리뷰 목록 화면으로 이동해야 한다. 그 화면이 이미 맨 위면 재사용하고 새로 쌓지 않는다.
- **FR-003**: 스캔 제안(SCAN_SUGGESTION) 알림 탭은 식사 시간과 동일하게 홈 탭으로 이동해야 한다. 이미 홈이면 그대로 둔다.
- **FR-004**: 리뷰 리마인더는 음식 상세(음식 id 필수), 소식은 이동 없음, 알 수 없는 유형은 이동 없음을 유지해야 한다.
- **FR-005**: 백그라운드 탭과 앱 종료 상태 탭(콜드스타트) 두 경로에서 같은 착지에 도달해야 한다.
- **FR-006**: 임시 착지 화면과 그 문구(10개 언어)를 제거해야 하며, 어떤 경로도 그 화면을 가리키지 않아야 한다.
- **FR-007**: 착지 매핑은 알림 유형만으로 결정하며 서버 데이터 형식 변경을 요구하지 않는다.
- **FR-008**: 유형별 매핑 테스트는 다섯 유형 + 알 수 없는 유형 + 리마인더 음식 id 부재를 모두 포함해야 한다.
- **FR-009**: 기존 푸시 데이터 계약 명세(specs/002)의 착지 표를 이 결정으로 갱신해야 한다.

### Key Entities

- **알림 유형→착지 매핑**: 다섯 유형 각각에 대한 목적 화면(또는 없음). 앱이 소유하며 서버는 관여하지 않는다.
- **탭 진입 경로**: 백그라운드 탭 / 종료 상태 탭. 둘 다 같은 매핑을 거친다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 다섯 유형 + 미지 + 리마인더 id 부재 7개 케이스의 착지가 유닛에서 100% 기대와 일치한다.
- **SC-002**: 식사 시간·리뷰 좋아요 알림이 백그라운드·종료 두 경로 모두에서 실기기(iOS·Android)로 기대 화면에 도달한다.
- **SC-003**: 임시 화면 파일·경로·문구 키가 소스와 10개 언어 파일에서 0건.
- **SC-004**: 타입 검사 0 오류, 전체 테스트 통과. JS 전용 변경이라 OTA 배포 가능.

## Assumptions

- 홈 = 앱의 첫 탭. 내 리뷰 목록 = 프로필 아래 "내 리뷰" 화면(이미 존재, 게스트 게이트 포함).
- 리뷰 좋아요 알림에 리뷰·음식 id가 없으므로 특정 리뷰로의 직접 이동은 범위 밖. 서버가 id를 실어 주면 별도 작업으로 상세 이동을 검토한다.
- 착지 결정 원칙: 서버는 유형과 대상 id만 보내고 화면 매핑은 앱이 가진다(2026-09-16 정리).
- 알림함(서버 전환, 별도 작업)에서 항목을 탭할 때도 같은 매핑을 쓰는 것이 목표지만, 그쪽은 서버 응답에 유형이 필요해 별도 논의다. 이 작업은 푸시 탭만 다룬다.
- 이 변경은 화면 경로 문자열만 바꾸므로 프레임 불변·메트릭 유닛 대상이 아니다.
