# Feature Specification: 알림 동의 바텀시트 모션 + 알림 문구 구분자 정리

**Feature Branch**: `003-notification-sheet-motion`

**Created**: 2026-09-14

**Status**: Draft

**Input**: User description: "553" — Jira KB-553 「[FE] 알림 동의 바텀시트 슬라이드 업·드래그/스크림 탭 닫힘 애니메이션 + 알림 문구 중간점→슬래시」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 알림 시트가 아래에서 올라오고 아래로 내려간다 (Priority: P1)

알림 권한 안내 시트(스캔 결과 직후)와 광고성 동의 시트(알림 설정에서 소식 켤 때)가 열릴 때 화면 아래에서 위로 미끄러져 올라온다. 닫힐 때는 반대로 아래로 미끄러져 내려간 뒤 사라진다. 지금은 둘 다 제자리에서 흐리게 나타났다 흐리게 사라진다.

**Why this priority**: 앱의 다른 하단 시트(온보딩 약관 시트)는 이미 올라오고 내려가는 모션을 쓴다. 알림 시트만 페이드라 같은 앱 안에서 시트 동작이 두 가지로 보인다.

**Independent Test**: 알림 설정에서 소식 토글을 켜 동의 시트를 연다. 아래에서 올라오는지, "나중에"를 눌렀을 때 아래로 내려가는지 눈으로 확인.

**Acceptance Scenarios**:

1. **Given** 시트가 닫힌 상태, **When** 시트가 열림, **Then** 시트가 화면 하단 밖에서 제자리까지 올라온다. 배경 딤은 함께 짙어진다.
2. **Given** 시트가 열린 상태, **When** "나중에"를 탭, **Then** 시트가 아래로 내려가 화면 밖으로 사라진 뒤 딤이 걷힌다.
3. **Given** 시트가 열린 상태, **When** 확인(알림 켜기 / 동의)을 완료, **Then** 같은 방식으로 아래로 내려간다.
4. **Given** 시트가 열린 상태, **When** Android 뒤로가기, **Then** 아래로 내려가며 닫힌다.

### User Story 2 - 시트를 끌어내리거나 배경을 눌러 닫는다 (Priority: P1)

사용자가 시트 어디든(손잡이·제목·본문·체크 행) 잡고 아래로 끌면 시트가 손가락을 따라 내려온다(2026-09-14 개정 — 이 시트는 내부 스크롤이 없어 손잡이 한정 사유가 없다). 충분히 끌거나 빠르게 튕기면 그대로 내려가 닫히고, 조금만 끌다 놓으면 원래 자리로 튕겨 돌아온다. 시트 바깥의 어두운 배경을 탭해도 시트가 아래로 내려가며 닫힌다.

**Why this priority**: 손잡이 표시가 이미 있는데 끌어도 아무 반응이 없어 사용자 기대와 어긋난다. 배경 탭 닫힘은 현재 되지만 모션 없이 사라진다.

**Independent Test**: 동의 시트를 열고 손잡이를 잡아 절반쯤 끌어내렸다 놓으면 복귀, 끝까지 끌면 닫힘. 배경 탭 시 내려가며 닫힘.

**Acceptance Scenarios**:

1. **Given** 시트 열림, **When** 손잡이를 잡고 아래로 조금 끌다 놓음(임계 미만), **Then** 시트가 원위치로 튕겨 돌아오고 열린 상태 유지.
2. **Given** 시트 열림, **When** 손잡이를 잡고 충분히 끌어내리거나 빠르게 아래로 튕김, **Then** 시트가 끝까지 내려가 닫힌다.
3. **Given** 시트 열림, **When** 배경 딤 영역 탭, **Then** 시트가 아래로 내려가며 닫힌다.
4. **Given** 끌어내리는 중, **Then** 배경 딤이 끌어내린 만큼 옅어진다.
5. **Given** 시트 열림, **When** 손잡이를 위로 끌어올림, **Then** 시트는 제자리에서 움직이지 않는다.
6. **Given** 동의 시트 열림, **When** 체크박스·"전문 보기"·확인 버튼을 탭, **Then** 끌기 제스처와 충돌 없이 각 동작이 그대로 실행된다(끌기는 손가락이 움직인 뒤에만 시작되므로 제자리 탭은 그대로 전달된다).
7. **Given** 닫히는 애니메이션 진행 중, **When** 다시 끌거나 배경을 탭, **Then** 닫힘이 한 번만 처리된다(중복 호출·되돌아옴 없음).
8. **Given** 시트를 닫았다가 다시 열림, **Then** 이전에 끌던 위치가 남지 않고 제자리에서 시작한다.

### User Story 3 - 알림 관련 문구의 중간점이 슬래시로 바뀐다 (Priority: P2)

알림 설정 화면과 알림 시트에 보이는 문구 가운데 항목을 중간점(·)으로 잇던 곳을 슬래시(/)로 바꾼다. 예: "리뷰 반응·식사 후 리뷰 작성" → "리뷰 반응/식사 후 리뷰 작성".

**Why this priority**: 표기 통일 요청. 기능 영향은 없지만 같은 화면 안에서 구분자가 섞이지 않게 한다.

**Independent Test**: 알림 설정 화면과 동의 시트를 열어 문구에 중간점이 남아 있지 않은지 확인. 10개 언어 모두 같은 키에서 확인.

**Acceptance Scenarios**:

1. **Given** 알림 설정 화면, **When** 활동 푸시·소식·식사 시간 항목의 부제를 읽음, **Then** 항목 구분자가 슬래시다.
2. **Given** 동의 시트, **When** 본문과 "마케팅 목적 개인정보 수집/이용 동의" 라벨을 읽음, **Then** 구분자가 슬래시다.
3. **Given** 한국어 외 언어, **When** 같은 문구를 봄, **Then** 그 언어 문구에 중간점이 있었다면 슬래시로 바뀌어 있고, 없었다면 그대로다.
4. **Given** 알림 설정·알림 시트 외 다른 화면, **Then** 문구가 바뀌지 않았다.

---

### Edge Cases

- 시트가 열리는 도중(올라오는 애니메이션 중) 배경을 탭하면 열림이 끝난 뒤 닫히거나 즉시 닫힘으로 전환되어야 하며, 시트가 중간에 멈춰 있으면 안 된다.
- 끌기 도중 OS 인터럽트(전화·알림 센터)로 제스처가 취소되면 시트는 원위치로 복귀한다.
- 확인 버튼이 처리 중(스피너)일 때 끌어내리거나 배경을 탭하면, 이미 시작된 확인 처리는 취소되지 않고 시트만 닫힌다. 동의 시트의 경우 처리 결과가 설정 화면에 반영된다.
- 화면이 큰 기기(태블릿·긴 폰)에서도 시트가 화면 밖까지 완전히 내려간다. 고정 거리로 내리면 안 된다.
- 접근성 "동작 줄이기" 설정이 켜진 기기에서는 모션이 짧아지거나 생략돼도 열림·닫힘 기능은 동일하게 동작한다.
- 시트 높이·패딩·손잡이 크기는 열림/닫힘/끌기 상태와 무관하게 동일하다. 상태로 바뀌는 건 위치와 딤 불투명도뿐.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 알림 시트(권한 안내·동의 두 변형 모두)는 열릴 때 화면 하단에서 위로 이동하며 나타나야 하고, 닫힐 때 아래로 이동하며 사라져야 한다. 닫힘 경로는 "나중에"·확인 완료·배경 탭·Android 뒤로가기·끌어내리기 전부다.
- **FR-002**: 시트 영역(스크림 제외) 어디서든 시작한 아래 방향 끌기에 시트가 손가락을 따라 이동해야 한다. 위 방향으로는 이동하지 않는다. (2026-09-14 개정: 손잡이·제목 한정 → 시트 전체)
- **FR-003**: 끌기를 놓았을 때 이동 거리 또는 속도가 임계를 넘으면 닫히고, 넘지 않으면 스프링으로 원위치 복귀해야 한다. 임계값은 앱의 기존 시트(온보딩 약관 시트)와 동일하다.
- **FR-004**: 끌어내린 거리에 비례해 배경 딤이 옅어져야 한다.
- **FR-005**: 체크박스·전문 보기·확인·나중에 버튼의 탭은 끌기 제스처와 충돌하지 않아야 한다. 끌기는 이동이 있어야 활성화되므로 제자리 탭은 버튼에 그대로 전달된다. (2026-09-14 개정)
- **FR-006**: 닫힘 처리는 한 번의 열림당 최대 한 번만 실행되어야 한다. 애니메이션 중 추가 입력은 무시된다.
- **FR-007**: 시트를 다시 열면 이전 끌기 위치가 초기화되어 제자리에서 시작해야 한다.
- **FR-008**: 닫힘 이동 거리는 시트의 실제 높이(측정값)여야 하며, 측정 전에는 화면 높이를 쓴다.
- **FR-009**: 시트의 레이아웃 치수(높이·패딩·라운딩·손잡이·체크박스 슬롯)는 모션 도입 전후 및 상태 전환 간에 동일해야 한다.
- **FR-010**: 알림 설정 화면과 알림 시트 문구 중 항목 구분에 쓰인 중간점(·)을 슬래시(/)로 바꿔야 한다. 한국어 기준 대상: 활동 푸시 부제, 소식 부제, 식사 시간 부제, 동의 시트 본문, 마케팅 개인정보 동의 라벨.
- **FR-011**: 10개 언어 파일에서 같은 키를 동일하게 처리해야 하며, 키 집합은 변하지 않는다. 다른 영역의 문구는 변경하지 않는다.
- **FR-012**: 제스처·모션 변경이므로 iOS·Android 실기기에서 열림·끌기·복귀·닫힘을 확인한 뒤에만 배포한다.

### Key Entities

- **알림 시트 상태**: 닫힘 / 열리는 중 / 열림 / 끌기 중 / 닫히는 중. 위치(세로 오프셋)와 딤 불투명도가 상태를 따른다.
- **끌기 임계**: 놓는 시점의 이동 거리와 속도. 기존 시트와 같은 값.
- **알림 문구 키**: 알림 설정 화면(`notif.*`)과 시트(`push.*`) 아래 문구. 10개 언어에 같은 키.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 두 변형 시트 모두 열림·닫힘 경로 5가지(나중에·확인·배경 탭·뒤로가기·끌기)에서 슬라이드 모션이 실기기 iOS·Android 각각 확인된다.
- **SC-002**: 임계 미만 끌기 100%가 원위치 복귀, 임계 초과 끌기 100%가 닫힘으로 끝난다(유닛 + 실기).
- **SC-003**: 시트 내부 탭 대상(체크박스 2·전문 보기 2·확인·나중에) 6개 모두 끌기 제스처 도입 후에도 탭 반응률 100%.
- **SC-004**: 한 번의 열림에서 닫힘 콜백 호출 횟수가 정확히 1회다(유닛).
- **SC-005**: 모션 도입 전후 시트 스타일 메트릭 비교 유닛이 통과한다.
- **SC-006**: 알림 설정·시트 문구 대상 키에서 중간점이 0건이고 10개 언어 키 집합 패리티 유닛이 통과한다.
- **SC-007**: 타입 검사 0 오류, 전체 테스트 통과. 변경은 JS 전용이라 OTA로 배포 가능하되 실기 확인 게이트를 거친다.

## Assumptions

- 끌어서 닫기 동작·임계·딤 페이드는 온보딩 약관 시트의 기존 동작을 그대로 따른다. 새 값을 정하지 않는다.
- 배경 탭 닫힘도 끌어내리기와 같은 "아래로 내려가는" 모션을 쓴다. 페이드나 즉시 사라짐은 허용하지 않는다.
- 권한 안내 시트(primer)와 동의 시트(consent)는 같은 컴포넌트의 두 변형이므로 모션도 함께 바뀐다. 한쪽만 바꾸지 않는다.
- 알림 설정 화면의 "소식 끄기" 확인 대화상자는 시트가 아닌 중앙 모달이라 이 작업 범위 밖이다.
- "전문 보기"는 외부 브라우저로 열리는 현재 동작을 유지한다.
- 중간점 치환 대상은 알림 설정 화면과 알림 시트 문구로 한정한다. 앱 전체의 중간점 표기 정책은 별도 결정.
- 스캔 결과 직후 권한 안내 시트가 뜨는 흐름(KB-497 결정)은 바뀌지 않는다.
